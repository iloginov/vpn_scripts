# Как обновить docs/clients_status.md

Инструкция для Claude: если пользователь просит "обнови clients_status.md" /
"посмотри кто подключался" — выполнить шаги ниже по каждому серверу и переписать
docs/clients_status.md (тот же формат: заголовок с датой, по одной секции/таблице
на сервер, отсортировано по убыванию свежести handshake, "никогда" — в конце).
Файл `docs/clients_status.md` в `.gitignore`: его можно переписывать локально,
в git не добавлять — там имена клиентов и адреса серверов.

Доступ: SSH-ключ уже добавлен в authorized_keys на всех четырёх серверах,
пользователь везде `vps`, sudo без пароля (NOPASSWD).
Не спрашивать пароль у пользователя — он не будет его давать, только ключ.

## Общая логика

1. Получить live-статус пиров: `wg show <iface> dump` или `awg show <iface> dump`
   (какой бинарник есть — тот и использовать, см. таблицу ниже). Первая строка
   вывода — это сам интерфейс (приватный/публичный ключ, порт, если это
   AmneziaWG — ещё и Jc/Jmin/.../H4), её нужно пропускать при разборе, это не пир.
   Формат остальных строк (tab-separated):
   `PublicKey  PresharedKey  Endpoint  AllowedIPs  LatestHandshake(unix ts)  RxBytes  TxBytes  PersistentKeepalive`
   `LatestHandshake == 0` значит "хендшейка не было с момента поднятия интерфейса".

   ВАЖНО: гонять команду одним ssh-вызовом БЕЗ примеси других команд в тот же
   stdout (например, не смешивать с `which wg` в одном redirect) — иначе строка
   интерфейса не на своём месте и парсер съедет. Лучше делать вызовы раздельно.

2. Получить имена клиентов — способ зависит от того, чем поднят сервер (см.
   таблицу серверов ниже): либо файл `clientsTable` (Amnezia app, сопоставление
   по PublicKey), либо `<server>.json` реестр от `awg_manage.py` (сопоставление
   по IP, т.к. в реестре нет публичных ключей клиентов).

3. Смёржить по ключу сопоставления, отсортировать по свежести, оформить таблицей
   Имя | IP | Последний handshake (дата+время + "N назад" на момент сбора).

4. Переписать docs/clients_status.md целиком (дата генерации в шапке, ссылка на
   этот файл, общее предупреждение про то, что это снимок с момента последнего
   рестарта демона/контейнера — не история).

## Таблица серверов

| Сервер | IP | Как поднят | Интерфейс(ы) | wg-бинарник | Где имена | Ключ сопоставления |
|---|---|---|---|---|---|---|
| A | <server-a-ip> | Приложение AmneziaVPN, Docker | Docker-контейнер `amnezia-awg`, внутри интерфейс `wg0` | `wg` (внутри контейнера) | `docker exec amnezia-awg cat /opt/amnezia/awg/clientsTable` (JSON, ключ `clientId` = PublicKey, `userData.clientName`) | PublicKey |
| B | <server-b-ip> | Приложение AmneziaVPN, Docker | Docker-контейнер `amnezia-awg2`, внутри интерфейс `awg0` | `wg` (внутри контейнера, есть и `awg`) | `docker exec amnezia-awg2 cat /opt/amnezia/awg/clientsTable` (тот же формат) | PublicKey |
| C | <server-c-ip> | Свои скрипты (`awg_manage.py`), без Docker, systemd `awg-quick@awg0`/`awg1` | `awg0` — реальные клиенты; `awg1` — обратный туннель самой ноды на exit (НЕ включать в отчёт) | `awg` (systemwide, `wg` может отсутствовать) | `~vps/awg/amneziawg_2_entry/server_awg0.json` на самом сервере (поле `ip`, публичных ключей клиентов там нет) | IP (AllowedIPs в дампе ↔ `ip` в реестре) |
| D | <server-d-ip> | Самая старая версия скриптов (`amneziawg_manage.py`), без Docker, systemd `awg-quick@awg0`/`awg1` | `awg0` — клиенты; `awg1` — транзит (не включать) | `awg` | Реестра нет. Имя = `<имя>` из `~vps/amneziawg_<timestamp>/client_<имя>.conf`; IP брать из строки `Address` (`grep -H '^Address' client_*.conf`) | IP; нормализовать к `/32` (в `client_test2.conf` опечатка `/24`) |

Проверять актуальность этой таблицы при каждом запуске: контейнеры могут
переименовать/добавить новую ноду — если что-то не совпало с ожиданиями
(`docker ps` не показывает ожидаемое имя, `clientsTable`/`server_awg0.json` не
находится по указанному пути), не гадать — поискать (`find`) и обновить эту
инструкцию заодно.

## На что обращать внимание / грабли, на которые уже наступали

- На сервере B есть пир `transit` (10.8.1.21, эндпоинт указывает на сервер C) —
  это межсерверный туннель entry→exit, не реальный клиент.
  Помечать примечанием, не выкидывать молча (мог оказаться значимым).
- На сервере C интерфейс `awg1` — это клиентская конфигурация самой ноды
  (в `/home/vps/awg1.conf` есть PrivateKey — значит это client-конфиг, не
  серверный). В отчёт по клиентам не включать.
- `latest handshake` — это НЕ история подключений, а текущее состояние
  интерфейса в памяти. Обнуляется при рестарте демона/контейнера. Если
  пользователь просит именно историю за прошлый период — такой истории просто
  нет физически, нужно предложить настроить сбор (cron, дампящий `wg show` в
  лог) и объяснить, что задним числом её взять неоткуда.
- Количество клиентов в реестре/clientsTable должно совпадать с количеством
  пиров в живом дампе — если не совпадает, значит где-то есть "осиротевший"
  пир без имени или клиент в реестре без соответствующего пира — упомянуть это
  явно пользователю, а не молчать.
- Никогда не приводить приватные ключи (PrivateKey, PresharedKey) в
  clients_status.md или в чат — они не нужны для отчёта, но легко утекают
  при копипасте сырого вывода `wg show`/`awg show`/конфигов.
- Пароли для SSH не запрашивать и не использовать, даже если пользователь
  предложит — ключ уже стоит на всех четырёх серверах.
- Сервер B 2026-09-20 не отвечал по SSH (timeout на порту 22). Если хост
  недоступен — не зависать на ретраях: собрать остальные, а секцию недоступного сервера оставить
  со старыми данными и явной пометкой "данные устарели, дата".
- Сервер D: у пира 10.10.1.2 нет файла client_*.conf — помечать как "???", не выкидывать.
- SSH-вызовы к разным серверам можно делать параллельно (`&` + `wait`), но не мешать stdout
  разных команд в один файл.
